# Админка, заявки, бронирование и данные

## 1. Назначение админки

Админ-панель нужна для управления сайтом без участия разработчика.

## 2. Роли пользователей

### Администратор

- полный доступ
- управление всеми разделами
- управление пользователями и заявками

### Менеджер

- обработка заявок
- работа с бронированиями
- редактирование части контента по правам

### Контент-менеджер

- тексты
- фото
- видео
- карточки услуг и кейсы

## 3. Модули админки

### Контент

- главная страница
- услуги
- кейсы
- о студии
- FAQ
- контакты

### Медиа

- фото
- видео
- логотипы
- обложки
- фоновые изображения

### Заявки

- список заявок
- фильтры по статусам
- комментарии
- история изменений

### Бронирование

- календарь занятости
- слоты времени
- подтверждение/отмена
- повторное открытие слота

## 4. Статусы заявки

- новая
- в обработке
- подтверждена
- отменена
- завершена

## 5. Основные сущности данных

Рекомендуемый набор сущностей:

- users
- roles
- pages
- services
- price_packages
- bookings
- booking_slots
- inquiries
- gallery_items
- videos
- faq_items
- settings
- media_files

## 6. Логика бронирования

### Пользовательский сценарий

1. Пользователь выбирает услугу.
2. Выбирает дату и время.
3. Отправляет заявку.
4. Заявка попадает в админку.
5. Администратор подтверждает или отклоняет её.
6. Клиент получает уведомление.

### Правила

- один слот не должен бронироваться дважды
- админ должен видеть занятые периоды
- должны учитываться длительность услуги и буфер между записями

## 7. Уведомления

Желательно предусмотреть:

- email-уведомления
- Telegram-уведомления для админа
- уведомления клиенту о статусе заявки

## 8. Минимальные требования к безопасности

- авторизация в админку
- разграничение ролей
- защита от спама в формах
- валидация всех входящих данных
