# Docker, Prisma и хранение контента

## Архитектура

Сайт, админка и API работают в одном Nuxt/Nitro-контейнере. Рабочие данные вынесены в постоянный Docker volume `studio313_data`:

```text
/app/data
├── site.sqlite     # Prisma/SQLite
├── uploads/        # изображения и другие загрузки
└── backups/        # подготовленные резервные копии
```

Docker-образ можно безопасно пересобирать: база и загрузки не входят в образ и не исчезают при обычной замене контейнера. Не удаляйте stack вместе с volumes без проверенной резервной копии.

## Переменные окружения

Минимальный production-набор:

```dotenv
PORT=3000
ADMIN_PASSWORD=replace-me
ADMIN_SESSION_SECRET=replace-with-a-long-random-string
DATABASE_URL=file:/app/data/site.sqlite
```

Compose дополнительно задаёт `NUXT_DATA_DIR=/app/data`. Для локальной разработки используется `DATABASE_URL=file:./data/site.sqlite`.

## Prisma 7

Проект использует Prisma 7, `@prisma/adapter-better-sqlite3` и SQLite. Схема находится в `prisma/schema.prisma`, история изменений — в `prisma/migrations`, а сгенерированный клиент — в `server/generated/prisma`.

Основные команды:

```shell
npm run db:generate
npm run db:migrate
npm run db:seed
npm run db:export-seed
npm run db:import
```

- `db:migrate` применяет ещё не выполненные миграции.
- `db:seed` вручную восстанавливает начальный снимок контента. Выполнение отмечается в таблице `DataMigration`.
- `db:export-seed` сохраняет полный снимок контента из текущей Prisma-базы в `prisma/seed-data.mjs`. Файлы изображений команда не копирует.
- `db:import` один раз переносит существующие JSON-настройки и legacy-файлы из `public/media/uploads`/`.output/public/media/uploads` в Prisma и постоянный каталог uploads.

После импорта JSON-файлы больше не являются рабочим источником данных. Страницы и админка читают и записывают контент только через Prisma.

## Запуск контейнера

При каждом старте `scripts/docker-entrypoint.sh`:

1. создаёт `/app/data/uploads` и файл базы, если их ещё нет;
2. выполняет `prisma migrate deploy`;
3. запускает `.output/server/index.mjs`.

Контейнер не запускает seed и импорт legacy-данных автоматически. Любые операции с контентом выполняются вручную.

## INITIAL RELEASE

Перед первой production-публикацией нужно зафиксировать полный начальный снимок контента:

1. закончить заполнение реализованных разделов через локальную админку;
2. выполнить `npm run db:export-seed`, чтобы перенести все заполненные данные из локальной Prisma-базы в `prisma/seed-data.mjs`;
3. проверить главную страницу, навигацию, секции «О студии», отзывы, услуги, features и waveform;
4. для каждого изображения оставить путь вида `/media/uploads/<имя-файла>`;
5. собрать все файлы, на которые ссылается seed, в отдельный архив uploads для первого развёртывания;
6. проверить seed на чистой локальной базе и закоммитить его вместе с актуальными миграциями.

Seed является снимком контента только для первоначального заполнения. После запуска production все последующие изменения выполняются через админку и сохраняются непосредственно в Prisma. Повторный seed не должен использоваться как способ обновления уже работающего контента.

После создания контейнера загрузить подготовленные изображения в постоянный volume:

```shell
docker cp ./initial-uploads/. studio313:/app/data/uploads/
docker exec --user root studio313 chown -R node:node /app/data/uploads
```

Затем вручную проверить миграции и выполнить начальное заполнение:

```shell
docker exec studio313 npm run db:migrate
docker exec studio313 npm run db:seed
```

`db:migrate` также выполняется entrypoint при старте, но повторная команда безопасна и явно подтверждает, что сервер находится на актуальной схеме.

Если production переносится именно со старых JSON-файлов, перед seed вручную выполнить:

```shell
docker exec studio313 npm run db:import
docker exec studio313 npm run db:seed
```

На чистом initial release, где весь утверждённый контент уже перенесён в `seed-data.mjs`, `db:import` запускать не нужно. Seed и legacy-импорт имеют отдельные маркеры в `DataMigration` и не выполняются повторно после успешного завершения.

## Что уже хранится в Prisma

- видимость пунктов навигации;
- главная страница и бегущая строка;
- секции страницы «О студии»;
- отзывы;
- избранные услуги, их особенности и данные waveform;
- метаданные загруженных изображений.

Кейсы, блог, FAQ, социальные ссылки и полный каталог тарифов пока остаются следующими этапами CMS.

## Изображения

Все новые изображения сохраняются только в постоянный каталог `data/uploads` (`/app/data/uploads` в контейнере) и доступны по адресу `/media/uploads/<file>`. В Prisma хранится публичный путь и метаданные файла, а не бинарное содержимое.

Новые загрузки нельзя записывать в `public`: этот каталог является частью одноразового Docker-образа. Файлы, найденные там старым импортёром, считаются legacy-данными и копируются в постоянное хранилище.

## Резервное копирование

Docker volume сам по себе не является резервной копией. Для полного восстановления нужны:

1. согласованная копия `site.sqlite`;
2. архив каталога `uploads`.

При работающей SQLite нельзя копировать только основной файл базы без учёта WAL. Используйте SQLite Backup API или `VACUUM INTO`, а затем архивируйте подготовленную базу вместе с uploads. Перед production-миграциями резервная копия обязательна.
