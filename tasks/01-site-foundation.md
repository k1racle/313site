# Задача 01. Фундамент публичного сайта

## Статус

Готова к выполнению.

## Цель

Создать с нуля фундамент публичного сайта Studio 313 на Nuxt 4, сохраняя
визуальное направление оригинального сайта, но не перенося его legacy-разметку,
CSS и JavaScript.

Результатом задачи должны стать:

- дизайн-система на Tailwind CSS 4;
- единая адаптивная оболочка публичного сайта;
- desktop sidebar по мотивам оригинала;
- mobile dock и полноэкранное мобильное меню;
- базовый компонент экранного перелистывания для мобильных страниц;
- рабочая маршрутизация и страницы-заглушки для будущих разделов.

Настоящий контент страниц будет добавляться отдельными задачами, блок за блоком.

## Архитектурное решение

### Единый layout

Использовать один публичный Nuxt-layout `default.vue` для desktop и mobile.

Не создавать отдельные layout по ширине экрана. Сервер Nuxt не знает реальную
ширину viewport, а выбор layout по User-Agent или после hydration создаёт риск
неверного SSR, мигания интерфейса, потери состояния и повторного монтирования
страницы.

Адаптивность реализовать внутри общей оболочки:

- на desktop отображается фиксированный левый sidebar;
- на mobile отображается нижний dock;
- mobile menu открывается отдельным полноэкранным слоем;
- контент страницы существует в DOM в одном экземпляре;
- переключение оболочки выполняется Tailwind-классами и media query.

Отдельные Nuxt-layout в дальнейшем использовать для интерфейсов другого типа,
например `admin.vue`, но не для адаптивных вариантов публичного сайта.

### Desktop и mobile страницы

URL, Nuxt Router и содержимое страниц остаются общими для всех устройств.

На desktop блоки страницы отображаются как обычная страница. На mobile те же
блоки могут быть обёрнуты в `ScreenFlow` и перелистываться как отдельные экраны.
Разметку блоков нельзя дублировать отдельно для desktop и mobile.

Первая версия `ScreenFlow` использует нативный CSS scroll snap. Подключать Swiper
или другую slider-библиотеку на этом этапе не нужно.

## Правила реализации

- Использовать Nuxt 4, Vue 3 и TypeScript.
- Следовать Feature-Sliced Design: `pages`, `widgets`, `features`, `entities`,
  `shared`.
- Не создавать пустые FSD-слои и искусственные сущности. `entities` появятся
  вместе с реальными моделями услуг, кейсов, команды и других данных.
- В шаблонах использовать только Tailwind-классы.
- Не создавать `<style scoped>` в компонентах.
- Не переносить классы и правила из `legacy.css`.
- `app.css` содержит только подключение Tailwind, токены темы, шрифты, базовые
  глобальные правила и необходимые глобальные анимации.
- Иконки интерфейса брать из `@nuxt/icon`, не переносить inline SVG из legacy.
- Логотипы использовать из существующих файлов `public/brand`.
- Не использовать JavaScript для определения desktop/mobile, если задачу решает
  CSS. Это исключает hydration mismatch.
- Учитывать `prefers-reduced-motion`.
- Не подключать публичный интерфейс к legacy API, серверу или админке.

## Этап 1. Отключение legacy

1. Перестать подключать `app/assets/css/legacy.css` в `nuxt.config.ts`.
2. Удалить `legacy.css` из Nuxt-приложения.
3. Удалить Nuxt-компонент `LegacySiteShell` и связанные с ним импорты.
4. Заменить текущую `index.vue`, которая рендерит legacy shell.
5. Не подключать `public/legacy/app.js` к новому приложению.
6. Оригинальные корневые `index.html`, `styles.css` и `app.js` оставить как
   визуальный и поведенческий референс.
7. Не изменять legacy-сервер и SQLite/API в рамках этой задачи.

## Этап 2. Tailwind 4 и app.css

Создать `app/assets/css/app.css` и подключить его в `nuxt.config.ts`.

В файле должны быть:

- `@import "tailwindcss"`;
- локальный `@font-face` для TT Firs;
- переменные и Tailwind-токены из `design.md`;
- базовые цвета: accent, accent-600, accent-700, accent-800, ink, text, muted,
  soft, white, page и panel;
- шрифты body и display;
- тени accent и panel;
- ширина sidebar `320px`;
- collapsed-ширина `112px`;
- основной page padding и section gap;
- основной и CTA-градиенты;
- длительности и easing анимаций;
- breakpoint оболочки `1080px`;
- минимальные base-правила для `html`, `body`, ссылок, кнопок и focus-visible;
- обработка `prefers-reduced-motion`.

Все токены, которые могут использоваться Tailwind-классами, объявить через
механизм темы Tailwind 4. Произвольные значения в шаблонах использовать только
там, где токен не оправдан.

## Этап 3. Общая оболочка

1. Привести `app.vue` к стандартной схеме `NuxtLayout` + `NuxtPage`.
2. Создать `layouts/default.vue`.
3. Разместить в layout постоянный `SidebarWrapper` и слот страницы.
4. Sidebar не должен пересоздаваться при каждом переходе между страницами.
5. На desktop рабочая область учитывает текущую ширину sidebar.
6. На mobile рабочая область учитывает высоту dock и safe area.
7. Изменение ширины sidebar должно быть плавным и не вызывать наложение
   контента.

## Этап 4. Desktop sidebar

Воспроизвести структуру оригинального sidebar, но написать компонент заново.

Сверху:

- белый логотип Studio 313;
- icon button для сворачивания и раскрытия sidebar.

В центре навигация:

- О студии;
- Услуги;
- Кейсы;
- Цены;
- Блог;
- Команда;
- Оборудование;
- Наши клиенты;
- FAQ;
- Контакты.

Снизу:

- email;
- телефон;
- адрес;
- ссылки на социальные сети;
- CTA `Записаться`.

Требования к поведению:

- раскрытая ширина `320px`;
- свёрнутая ширина `112px`;
- в collapsed-состоянии остаются логотип-маркер и иконки навигации;
- состояние сохраняется в `localStorage` после hydration;
- активный пункт определяется через текущий Nuxt route;
- ссылки реализованы через `NuxtLink`;
- hover и active состояния соответствуют `design.md`;
- декоративный градиент не мешает читаемости;
- кнопки имеют доступные названия и focus-visible состояние.

Навигацию, контакты и ссылки хранить централизованно в `shared/config`, а не
дублировать между desktop sidebar и mobile menu.

## Этап 5. Mobile dock и меню

При ширине меньше `1080px` desktop sidebar скрывается и появляется нижний dock.

Dock содержит:

- логотип;
- кнопку звонка;
- кнопку открытия меню.

Требования:

- фиксированное положение снизу;
- высокий, но системно определённый z-index;
- учёт `env(safe-area-inset-bottom)`;
- touch target кнопок не меньше 44x44 px;
- контент страницы не перекрывается dock-панелью;
- фон и движение визуально связаны с desktop sidebar.

Mobile menu:

- полноэкранный слой над страницей, но под dock либо согласованно с ним;
- использует тот же список навигации, что desktop sidebar;
- закрывается по Escape;
- закрывается после выбора ссылки;
- закрывается при изменении route;
- блокирует прокрутку фоновой страницы;
- корректно управляет `aria-expanded` и `aria-controls`;
- возвращает фокус на кнопку меню после закрытия;
- не рендерит второй экземпляр контента страницы.

## Этап 6. ScreenFlow

Создать основу для различной композиции страниц на desktop и mobile.

На desktop:

- `ScreenFlow` не ограничивает высоту страницы;
- `ScreenSlide` ведёт себя как обычная секция;
- блоки идут в стандартном вертикальном потоке.

На mobile:

- `ScreenFlow` становится горизонтальным scroll-контейнером;
- используется `scroll-snap-type: x mandatory`;
- каждый `ScreenSlide` занимает доступную ширину viewport;
- высота учитывает mobile dock и safe area;
- длинный контент внутри экрана может прокручиваться вертикально;
- наружный компонент сообщает активный индекс;
- поддерживаются touch-жесты и стрелки клавиатуры;
- плавная прокрутка отключается при `prefers-reduced-motion`.

Не реализовывать бесконечный цикл, autoplay, drag-физику или виртуализацию. Если
после появления настоящих страниц нативного scroll snap окажется недостаточно,
slider-библиотека будет выбрана отдельным решением.

## Этап 7. Маршрутизация и демонстрация

1. Главная страница должна содержать три простых демонстрационных блока:
   `Главная`, `О студии`, `Услуги`.
2. На desktop блоки отображаются как обычная страница.
3. На mobile блоки перелистываются через `ScreenFlow`.
4. Создать временную страницу `[slug].vue` для ещё не реализованных разделов.
5. Разрешать только slug, описанные в конфигурации навигации.
6. Неизвестные slug должны возвращать Nuxt 404.
7. По мере реализации настоящие статические страницы будут заменять временный
   dynamic route.
8. Для заглушек задать базовые title и description через Nuxt SEO API.

## Вне задачи

- Перенос настоящих hero, услуг, кейсов и остальных блоков.
- SQLite и схема базы данных.
- Серверные API.
- Админка.
- Бронирование и CRM-виджет.
- Перенос legacy-анимаций целиком.
- Loader, spotlight, grain и сложные переходы между страницами.
- Заполнение реальных ссылок на социальные сети, если данных пока нет.

## Проверка

Проверить интерфейс минимум в следующих viewport:

- `1440x900` — раскрытый и свёрнутый sidebar;
- `1080x800` и соседние ширины — переход между оболочками;
- `768x1024` — планшет;
- `390x844` — мобильный экран;
- мобильный viewport с safe area.

Проверить сценарии:

- переход по каждому пункту навигации;
- прямое открытие URL;
- browser back/forward;
- active-состояние ссылки;
- сохранение collapsed-состояния;
- открытие и закрытие mobile menu;
- Escape и управление фокусом;
- горизонтальное перелистывание экранов;
- вертикальная прокрутка длинного экрана;
- отсутствие перекрытия контента mobile dock;
- отсутствие hydration warning и ошибок в консоли.

Выполнить команды:

```bash
npm run lint
npm run typecheck
npm run build
```

## Критерии готовности

- Nuxt больше не загружает `legacy.css` и legacy JavaScript.
- `app.css` подключён и содержит дизайн-токены из `design.md`.
- В компонентах нет собственных CSS-блоков и legacy-классов.
- Публичный сайт работает через единый адаптивный layout.
- Desktop sidebar полностью раскрывается и сворачивается.
- Mobile dock и полноэкранное меню работают и доступны с клавиатуры.
- Все пункты навигации ведут на валидные URL.
- Одна и та же разметка блоков используется на desktop и mobile.
- Демонстрационные блоки становятся mobile-экранами без дублирования.
- Нет наложений интерфейса на проверенных viewport.
- Lint, typecheck и production build завершаются успешно.
